# AxisNow 边缘部署

本文将 AxisNow 作为本系统唯一的边缘入口，承担 TLS、缓存、访问控制、限流、回源保护和日志观测。规则按 AxisNow 已发布的“真实客户端 IP”“通用访问控制”“速率控制”“缓存控制”“回源连接控制”等插件设计。

> 除非确实需要全球与中国大陆的多 CDN 调度，否则优先使用本章的单 CDN 架构。它更容易验证真实 IP、缓存命中和故障来源。

## 架构和前置条件

```text
浏览器 -> AxisNow Edge -> Caddy -> Nuxt/Nitro
```

1. 在 AxisNow 创建业务域及源地址，将源地址设为 Caddy 的 HTTPS 地址。
2. 业务域 DNS 仅指向 AxisNow 提供的接入地址；不要留下可被用户直接访问的源站 A/AAAA 记录。
3. 源站防火墙只允许 AxisNow 回源出口访问 443；如果 Caddy 与 Nuxt 同机，Nuxt 仅监听 `127.0.0.1:3000`。出口 IP 范围须以实际订阅的边缘配置为准。
4. 在 Caddy 与 Nuxt 同机时设置：

```dotenv
TRUSTED_PROXY_IPS=127.0.0.1,::1
```

1. 在 AxisNow 策略中先启用“真实客户端 IP”，将真实地址覆写到 `X-Forwarded-For`。本应用仅当 TCP 对端是 `TRUSTED_PROXY_IPS` 时才读取转发头，并依次读取 `X-Forwarded-For`、`CF-Connecting-IP`、`X-Real-IP`。
2. 不要允许客户端携带的同名转发头原样到达源站。应在边缘覆写，且源站不得绕过 AxisNow 暴露，否则攻击者可以伪造 IP 并绕过策略。

AxisNow 的真实客户端 IP 插件支持向上游传递真实地址；其条件字段文档建议使用 `X-Forwarded-For` 或 `X-Real-IP` 获取实际客户端地址。上线前在 AxisNow 访问日志和后台操作日志中分别确认同一次管理员访问的地址一致。

## 策略顺序

为业务域创建一条策略，按以下顺序放置插件。界面名称可能随 AxisNow 版本调整，匹配字段以其[条件匹配字段](https://www.axisnow.io/zh/docs/edge/policies/plugins/tiao-jian-pi-pei-zi-duan)为准。

1. SSL/TLS 与 HTTP 跳转：仅允许 HTTPS，将 HTTP 重定向到 HTTPS。
2. 真实客户端 IP：覆写并转发 `X-Forwarded-For`。
3. 通用访问控制：执行请求方法、请求体及异常流量规则。
4. 缓存控制：仅缓存本章允许的公开 `GET`/`HEAD` 路径。
5. 速率控制：按真实客户端地址计数，设置请求与回源两类阈值。
6. 回源连接控制、健康检查和重试：保护 Caddy/Nitro 与外部音源。
7. 访问日志与告警：记录命中规则、缓存状态、状态码及回源耗时。

## 缓存规则

缓存控制插件支持自定义缓存 Key、TTL 和缓存清理；本系统所有缓存规则均要求方法为 `GET` 或 `HEAD`。

| 优先级 | 条件                                                                        | 边缘与浏览器 TTL         | 缓存键与说明                                                                                |
| ------ | --------------------------------------------------------------------------- | ------------------------ | ------------------------------------------------------------------------------------------- |
| 1      | `http.request.uri.path` 以 `/_nuxt/` 开头                                   | 尊重源站响应头           | 保留默认完整 URL；构建资源带内容哈希，无需手动清理。                                        |
| 2      | 路径为 `/api/cover/meting` 或 `/api/cover/netease`                          | 尊重源站 `Cache-Control` | 必须保留全部查询参数，特别是 `server`、`id`、`size`。Meting 封面为 30 天，网易封面为 1 天。 |
| 3      | 路径为 `/api/site`、`/api/playlist/recent`，或以 `/api/playlist/date/` 开头 | 尊重源站 `Cache-Control` | 源站当前为 30 秒，键保留完整 URL。                                                          |
| 4      | 其他所有请求                                                                | 不缓存或绕过             | 作为默认兜底规则。                                                                          |

以下路径必须显式绕过缓存：`/api/admin/`、`/api/request`、`/api/request/challenge`、`/api/requests/lookup`、`/api/search/song`、`/api/stream/`、`/api/health`，以及一切非 `GET`/`HEAD` 请求。它们分别涉及认证、写操作、隐私查询、第三方搜索、Range 音频流或健康探测；其中音频流响应为 `no-store`。

缓存清理时，优先清理单个完整封面 URL。仅在确实需要全部失效时才按 `/api/cover/` 前缀清理。不能忽略查询参数，否则不同歌曲会返回错误封面。

## 通用访问控制

先以“记录”模式观察 24 至 48 小时，再对确定异常的规则改为阻断或挑战。以下规则不影响后台已有的 `PUT`、`PATCH`、`DELETE` 操作。

| 条件                                                                | 动作                        | 理由                                                   |
| ------------------------------------------------------------------- | --------------------------- | ------------------------------------------------------ |
| `http.request.scheme` 为 `http`                                     | 301/308 跳转 HTTPS          | 统一加密入口。                                         |
| 路径以 `/api/request` 开头，且 `http.request.body.size` 大于 64 KiB | 阻断，返回 413 或统一错误页 | 点歌和 PoW 内容很小，大请求体没有业务价值。            |
| 路径为 `/api/request/challenge`，方法不是 `POST`                    | 阻断                        | 缩小 PoW 接口暴露面。                                  |
| 路径为 `/api/request`，方法不是 `POST`                              | 阻断                        | 缩小点歌写入接口暴露面。                               |
| 路径为 `/api/search/song`，方法不是 `GET`                           | 阻断                        | 该接口只读。                                           |
| 已确认的攻击 IP、ASN 或异常路径                                     | 临时阻断                    | 有证据时精准处置；不要因单次失败直接封禁共享校园出口。 |

不要以 User-Agent 单独识别搜索引擎或机器人，且不要将一次鉴权失败直接封禁 IP。AxisNow 的防 CC 指南也建议先按业务画像分层处置，避免 NAT、学校或家庭共享出口被误伤。

## 速率控制

启用“速率控制”插件，并确保它位于真实客户端 IP 插件之后。计数维度选实际客户端地址；若当前配置只能使用 `ip.src`，先确认它不是上游代理地址。AxisNow 支持请求阈值与回源阈值独立设置，以下是适合校园公开点歌站的起始值，而非不可变的安全边界。

| 优先级 | 匹配条件                      | 请求阈值（单客户端） | 回源阈值（单客户端） | 超限动作                           |
| ------ | ----------------------------- | -------------------- | -------------------- | ---------------------------------- |
| 1      | `POST /api/request`           | 20 次 / 10 分钟      | 20 次 / 10 分钟      | 返回 429；保留应用 PoW。           |
| 2      | `POST /api/request/challenge` | 60 次 / 10 分钟      | 60 次 / 10 分钟      | 返回 429；不要直接永久封禁。       |
| 3      | `GET /api/search/song`        | 90 次 / 分钟         | 90 次 / 分钟         | 返回 429。                         |
| 4      | `GET /api/requests/lookup`    | 60 次 / 分钟         | 60 次 / 分钟         | 返回 429。                         |
| 5      | 路径以 `/api/stream/` 开头    | 新请求 30 次 / 分钟  | 新请求 30 次 / 分钟  | 返回 429；不缓存、不重试流。       |
| 6      | 路径以 `/api/cover/` 开头     | 180 次 / 分钟        | 30 次 / 分钟         | 边缘优先命中缓存，限制冷缓存回源。 |
| 7      | 路径以 `/api/admin/` 开头     | 120 次 / 分钟        | 120 次 / 分钟        | 返回 429；登录另见下一行。         |
| 8      | `POST /api/admin/login`       | 15 次 / 10 分钟      | 15 次 / 10 分钟      | 返回 429；不因首次失败封禁。       |
| 9      | 其余以 `/api/` 开头的请求     | 180 次 / 分钟        | 180 次 / 分钟        | 返回 429。                         |

同一 NAT 出口内用户仍会共享边缘按 IP 的配额，因此阈值刻意高于单人使用量。若从访问日志发现共享出口接近阈值，先提升该路径的正常阈值或对其启用挑战，不要立即封禁。只有存在持续攻击时，才使用短期封禁和自动缓解。

`INTERNAL_RATE_LIMIT_ENABLED=false` 只能在以上规则已发布、真实 IP 已验证、源站已禁止直连后设置。该开关会关闭应用内搜索/试听/点歌的按 IP 计数、每日点歌配额和试听并发计数；不会关闭 PoW、一次性 nonce、防重放、输入校验和管理员鉴权。

```dotenv
INTERNAL_RATE_LIMIT_ENABLED=false
```

## 回源可靠性和容量

1. 启用回源连接控制，为 Caddy/Nitro 设置符合主机容量的连接池、连接超时和首字节超时；先用压测和日志确定容量，不能照搬固定数字。
2. 健康检查使用 `GET /api/health`，该接口为 `no-cache`；将检查 Host 设置为业务域名，避免虚拟主机误判。
3. 只对幂等的 `GET`/`HEAD` 在 502、503、504 时尝试一次回源重试。不得重试 `POST /api/request`、PoW、登录和任何 `/api/admin/` 写操作，以免重复执行。
4. `/api/stream/` 是长连接音频代理：设置足以覆盖试听时长的读取超时，不缓存，不在响应体传输中重试。
5. 对 `/api/cover/` 启用缓存分片或请求合并（若当前插件版本提供），降低首个冷缓存封面同时回源到音乐平台的概率。

## 日志、告警和上线流程

1. 打开 AxisNow 访问日志，至少记录路径、方法、状态码、真实客户端地址、命中策略、缓存命中/回源、回源耗时、上游状态码和 User-Agent。
2. 为回源 5xx、回源延迟上升、429 激增、缓存命中率下降、健康检查失败设置告警。
3. 首日仅记录限流命中，检查校园 NAT 出口、课间流量峰值和封面冷缓存表现。
4. 第二阶段启用 429 处置；受到攻击时再启用挑战和自动缓解。每次调整后保留一周日志并复盘阈值。
5. 从外网直接访问源站 IP 或旧域名应失败；若成功，先修复源站访问控制，再关闭应用内限流。

## AxisNow 与 Cloudflare 双 CDN

AxisNow 的[双 CDN 指南](https://www.axisnow.io/zh/docs/guide/axisnow-cloudflare)适合“全球主要使用 Cloudflare、中国大陆需要专门优化节点”的业务。它使用 AxisNow DNS 路由，在中国大陆调度到 AxisNow Edge，其余区域调度到 Cloudflare。

该架构的前提是 Cloudflare 的合规 CNAME 接入能力，例如付费 Partial setup 或 Cloudflare for SaaS 自定义主机名；不要将任意 Cloudflare 边缘地址作为调度目标，AxisNow 文档明确指出这违反 Cloudflare 服务条款。它还增加虚拟域、回源域、调度域、拨测和双侧规则同步成本。

本系统的推荐顺序：

1. 先部署本章单 AxisNow 架构并稳定运行。
2. 有明确的跨境访问需求、Cloudflare 合规方案和持续运维能力时，再采用双 CDN。
3. 双 CDN 时，两侧都必须应用相同的“不可缓存路径”“请求体限制”“速率控制”和源站锁定规则；不要只在其中一侧配置防护。
4. 调度健康检查分别使用与最终用户地区对应的中国大陆和国际拨测点。初次配置后等待数分钟让监控初始化，再启用基于健康状态的切换。

AxisNow 规则能力与字段请以[插件列表](https://www.axisnow.io/zh/docs/edge/policies/plugin-list)及[条件匹配字段](https://www.axisnow.io/zh/docs/edge/policies/plugins/tiao-jian-pi-pei-zi-duan)为准；控制台未公开的具体字段名称不应凭经验替换。
